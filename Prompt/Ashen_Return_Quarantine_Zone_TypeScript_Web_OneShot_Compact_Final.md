# 잿빛 귀환: 격리구역 — TypeScript 웹 2D 픽셀아트 탈출형 슈터 원샷 개발 프롬프트

이 문서는 **단독 실행 가능한 제품 명세이자 구현 프로토콜**이다. 외부 문서나 별도 게임을 전제로 하지 말고, 이 문서 하나를 canonical specification으로 사용해 프로젝트 초기화 → 구현 → 실행 → 테스트 → 수정 → 완주 → production 정적 빌드 검증까지 수행하라.

최종 목표는 코드 양이 아니라 **브라우저에서 처음부터 끝까지 실제 플레이되고, 저장·재실행·복구되며, 핵심 규칙이 자동 테스트와 E2E 증거로 검증되는 완성된 Chapter 1 게임**이다.

---

## 0. 실행 계약

### 요구 등급

- **LOCKED**: 깨지면 게임 상태나 핵심 설계가 잘못되는 불변 규칙. 자원 보존, 단일 소유권, 피해·충돌 순서, 탄약·탄창 보존, 중복 트랜잭션 방지, 사망/탈출 우선순위, 저장 복구, 실제 탄도 기반 머리/몸 판정, 플레이어·AI의 핵심 전투 규칙 공유가 여기에 속한다.
- **TUNABLE**: 피해·가격·거리·시간·AI 반응·맵 크기·EXP·Perk·날씨·경제 등 초기값. 실제 플레이·성능·가독성 검증에서 조정할 수 있으나 이전 값/새 값/이유/영향/검증 결과를 기록한다.
- **CREATIVE**: 세부 맵 형태, 소품 배치, 대사, 아이템 이름, 미세 애니메이션 등 제품 방향을 해치지 않는 범위에서 구현자가 결정할 영역이다.

### 구현 우선순위

- **P0 — Core Vertical Slice**: 새 슬롯 → 거점 → 장비 준비 → 첫 출격 → 전투/루팅 → 탈출 → 반입 → 저장 → 브라우저 재로드 복원.
- **P1 — Chapter 1 Complete**: 본 문서의 전체 첫 완성판. 총기 12종, 출격지 2개, Region 6개, 실내 4개, 적 역할 4종+보스, Q01~Q08, NPC 3명, EXP/Perk, 건설/시설, 시간/날씨, 상점/블랙마켓, 계약/이벤트, 제작/수리/분해, 노트/열쇠, 저장 슬롯/복구, Chapter 1 결말과 자유 출격.
- **P2 — Expansion & Hardening**: 추가 콘텐츠 팩, 심화 세이브 버전 호환, 선택적 절차 지형, 농장/펫/생존 프리셋/추가 챕터 등. P1 완주 전 우선하지 않는다.

### 전역 불변 규칙

1. authoritative state는 TypeScript 게임 상태 계층에 둔다. Phaser Scene, UI, 애니메이션, 파티클, 오디오가 체력·탄약·화폐·퀘스트를 직접 바꾸지 않는다.
2. 아이템·탄약·화폐·내구도·보상은 생성/소멸/이전 경로가 추적 가능해야 하며 실패·저장·재시도 때문에 복제·유실되지 않는다.
3. 하나의 authoritative 아이템 인스턴스는 동시에 둘 이상의 소유 컨테이너에 존재하지 않는다.
4. 안정 ID를 가진 동일 거래·보상·탈출·사망 이전은 반복 실행되어도 한 번만 커밋된다.
5. 표현과 판정을 분리한다. 예광선·스프라이트·효과음·카메라 흔들림은 실제 탄도·충돌·AI 청각의 근거가 아니다.
6. 게임 규칙은 렌더 FPS와 분리한다. **60Hz fixed-step simulation**을 기본으로 하고 렌더 보간은 표현에만 사용한다.
7. authoritative 난수에 `Math.random()`을 쓰지 않는다. `world/loot/enemy/combat/weather/contract/market/cosmetic` RNG stream을 seed 기반으로 분리한다.
8. 테스트를 통과시키기 위해 제품 요구나 expectation을 이유 없이 약화하지 않는다.
9. typecheck/build 성공, 자동 테스트, 브라우저 런타임, 시각 검수, 인간 QA는 서로 다른 검증 상태다.
10. 중요 상태는 `beforeunload`에 의존하지 않는다. 거래·탈출·사망·퀘스트 보상·체크포인트는 그 전에 IndexedDB에 안전하게 커밋한다.
11. 기본 게임은 서버·로그인·원격 DB 없이 **정적 HTTP(S) 호스팅**만으로 Chapter 1 전체가 동작해야 한다.
12. P0/P1 완성도를 미래 추상화보다 우선한다. 새 콘텐츠는 데이터 정의 추가로 확장할 수 있게 하되 사용하지 않는 범용 프레임워크를 먼저 만들지 않는다.

### 검증 상태

`NotStarted | InProgress | Implemented | AutoVerified | RuntimeVerified | VisualVerified | ManualQARequired | Blocked | Failed`

`Implemented`를 `Verified`로 보고하지 마라.

### 원샷 행동

환경과 저장소 지침을 확인한 뒤 실제 구현을 시작하라. 계획만 작성하고 끝내지 마라. 사소한 미정사항은 CREATIVE/TUNABLE로 결정한다. 현재 Stage Gate에 차단되지 않은 필수 항목이 남아 있으면 계속 구현·테스트·수정한다. 긴 작업은 `ProjectState`를 갱신해 다음 context에서 바로 이어갈 수 있게 한다.

## 1. 제품 정의

**게임명:** 「잿빛 귀환: 격리구역」 / `Ashen Return: Quarantine Zone`

**장르:** 한국어 싱글플레이 PvE 2D 픽셀아트 탐험·루팅·탈출·거점 성장형 슈터.

플레이어는 폐쇄된 격리구역의 지하 대피소에 정착한 의인화된 조류 생존자다. 거점에서 장비를 준비하고 위험 지역에 출격해 소리·엄폐·탄약·부상을 관리하며 물자를 회수한다. 목표는 많은 적을 죽이는 것이 아니라 살아 돌아와 대피소의 전력·통신을 복구하고 더 위험한 지역과 장비를 열어 가는 것이다.

한 번의 일반 출격은 **10~20분**을 목표로 한다. 강제 제한시간은 기본 OFF이며 탄약, 부상, 중량, 전리품 가치, 시간대/날씨, 남은 탈출 경로가 귀환 결정을 만든다.

반복 판단은 다음 다섯 가지가 중심이다.

- 싸울 것인가 우회할 것인가.
- 빠른 몸샷인가 위험한 헤드샷인가.
- 싸고 흔한 탄인가 비싸고 관통력 높은 탄인가.
- 생존 자원을 남길 것인가 고가 전리품을 더 챙길 것인가.
- 더 탐색할 것인가 현재 성과를 지키고 탈출할 것인가.

### Chapter 1

- **프롤로그 — 돌아갈 곳:** 대피소와 물자 부족, 첫 출격 필요성.
- **1막 — 살아 돌아오기:** 농장·수로 탐색, 의료품·부품 확보, 조직적인 순찰대의 흔적.
- **2막 — 불을 다시 켜다:** 작업대·발전기 복구, 제작·상점·깊은 지역 해금.
- **3막 — 끊긴 신호:** 통신 복구 후 격리구역 밖의 반복 암호 신호 포착.
- **4막 — 마지막 신호:** 산업 시설 지휘관 처치, 암호 모듈 회수, 생환.
- **에필로그 — 신호의 바깥:** Chapter 1은 완결하고 자유 출격을 유지하며 다음 지역의 존재만 암시한다.

스토리는 긴 컷신보다 짧은 NPC 대화, 임무 설명, 라디오, 시설 상태 변화, 환경 흔적, 노트·아이템 설명으로 전달한다.

## 2. 기술 스택과 프로젝트 구조

기본 스택은 다음으로 고정한다.

- **TypeScript `strict`**
- **Phaser 4**: 2D 렌더링, 입력, 오디오, scene lifecycle
- **Vite**: dev/build/preview
- **Vitest**: deterministic unit/simulation/integration test
- **Playwright**: 실제 브라우저 E2E
- **IndexedDB**: 프로필/출격/백업 저장
- Node.js current LTS + lockfile 기반 재현 가능한 패키지 설치

`package.json`에 최소 다음 진입점을 둔다.

```text
npm run dev
npm run typecheck
npm run test
npm run test:e2e
npm run build
npm run preview
npm run verify
```

권장 경계:

```text
src/
  core/          # fixed clock, ids, events, rng, transactions
  combat/        # aim, weapon, projectile, damage, armor, cover
  inventory/     # items, containers, equipment, ownership
  world/         # maps, regions, interactions, loot, exits, weather
  ai/            # senses, navigation, behavior
  progression/   # quests, contracts, exp, perks, flags
  economy/       # traders, market, crafting, repair, buildings
  save/          # schema, IndexedDB, journal, backup, import/export
  presentation/  # Phaser scenes, sprites, animation, audio, effects
  ui/            # HUD, menus, panels, localization, accessibility
  content/       # definitions and registries
  debug/
tests/
e2e/
public/
ProjectState/
```

핵심 규칙은 Phaser object에 숨기지 말고 순수 TypeScript 상태/함수로 테스트 가능하게 유지한다.

## 3. 화면, 픽셀 규격, 좌표와 입력

### 렌더링

- 월드 기준 해상도 **640×360**.
- 기본 지면 타일 **16×16px**.
- 캐릭터 프레임 캔버스 **32×48px**.
- 월드는 nearest/point sampling과 정수 배율을 우선하고 남는 공간은 레터박스 처리한다.
- UI는 별도 고해상도 레이어에서 렌더해 한글 가독성을 보존한다.
- `devicePixelRatio`는 성능상 최대 2 정도로 제한 가능한 TUNABLE 값으로 둔다.
- CSS canvas 크기, backing size, 논리 월드 좌표를 혼동하지 않는다.

### 전술 좌표

지면 이동은 `(x,y)`, 논리 높이는 `z`를 사용한다. `z`는 층 높이와 자세/부위 높이를 표현하며 렌더 정렬용 Y 값과 분리한다.

기본 화면 투영:

```text
S = C + k × (16x, 16y - 16z)
```

특정 `z`가 주어졌을 때만 화면 좌표를 논리 좌표로 복원한다.

```text
x = (Sx-Cx)/(16k)
y = (Sy-Cy)/(16k) + z
```

커서, 목표 선택, 총구, 투척 궤적, 타일 정렬은 같은 좌표 모듈을 사용한다.

### 카메라

- 기본 커서 방향 선행 최대 **6u**.
- 스코프는 전방 관측 여유와 안정성만 늘리고 벽 뒤 정보를 공개하지 않는다.
- 카메라 흔들림·보간·줌은 실제 조준 벡터와 탄도를 바꾸지 않는다.
- 30/60/144 렌더 FPS, DPR 1/1.25/1.5/2, resize/fullscreen 후 목표점 투영 오차를 **1 내부 픽셀 이하**로 시작한다.

### 조작

```text
WASD/방향키 이동
마우스 조준
LMB 발사
RMB 정밀 조준
R 재장전 / 0.25초 내 R 두 번 빠른 장전
B 발사 모드
Shift 달리기
C 웅크리기
E 상호작용
Tab 인벤토리
1,2 주무기 / 3 보조무기 / 4~7 퀵슬롯
V 근접
G 투척
M 지도
Esc 일시정지
```

전부 재설정 가능하게 하되 `Ctrl+R`, `Ctrl+W`, `F5` 같은 브라우저 예약 조합은 할당하지 않는다. 게임 canvas가 포커스를 가질 때만 필요한 기본 브라우저 동작을 차단한다. 포커스 상실·pointer leave 시 유지 발사 입력을 즉시 해제한다.

### 근접 커서 안정화

조준 기준점은 안정된 몸통/어깨 앵커다. 기준 뷰에서 커서가 12px 안으로 들어오면 마지막 유효 방향을 유지하고 18px 밖에서 갱신을 재개한다. 계산 순서는 **조준 앵커 → 유효 목표 → 방향 → 신체/무기 포즈 → 손/총구 소켓**이다. 총구에서 다시 커서를 조준해 총구가 재계산되는 순환을 금지한다. 0벡터·NaN·360도 회전 폭주·좌우 flip 진동을 테스트한다.

## 4. 월드, 출격지, 시간과 날씨

### 출격 구조

- `MapDef`: 한 번의 출격 단위. raid seed, 전역 상태, Region 연결, 출입구, 저장 경계.
- `RegionDef`: 전투·전리품·환경·이벤트가 구분되는 논리 지역.
- `TravelDestinationDef`: 거점에서 선택하는 Map, 해금 조건, 비용, 예보, 위험도, 시작점.
- Interior는 Region에 속하는 실내 공간이며 같은 월드 또는 비동기 chunk로 구성할 수 있다.

### P1 출격지

**A. 격리구역 본토 (`core.map.quarantine_main`)**

- 약 96×96u, 10~20분.
- 버려진 농장: 짧은 시야·중거리, 의료/식량/초급 재료, 기울어진 급수탑.
- 수풀 수로: 갈대·진흙·얕은 물, 우회와 이동 소음, 붉은 배수 펌프.
- 무너진 검문소: 콘크리트·차체, 긴 사선과 측면 접근, 탄약/장비.
- 폐쇄 산업 시설: 실내외 전환, 문·높은 벽, 고급 부품과 최종 목표.
- 필수 실내: 농장 창고, 수로 펌프실, 산업 시설 통제실.

**B. 외곽 보급로 (`core.map.outer_supply_route`)**

- 약 64×80u, 8~14분.
- 폐선 화물역 + 침엽림 보급창 + 폐쇄 화물창고 1개.
- Q03 이후 해금.
- 더 긴 사선, 적은 탈출점, 탄약/부품/열쇠/시장 단서 비중 증가.
- 본토보다 야간/악천후 확률이 높다.

맵 수를 채우기 위해 색만 바꾼 복제품을 만들지 않는다. 지형, 교전거리, 엄폐 재질, 전리품, 탈출 조건, 오디오가 실제로 달라야 한다.

### 시간대

`Day | Dusk | Night`

- Day: 기준값.
- Dusk: 조도 감소와 실루엣 대비 변화.
- Night: 시야·AI 관측 거리 감소, 조명/야간 장비 가치 증가.

### 날씨

`Clear | Cloudy | Rain | Storm`

TUNABLE 시작점:

| 상태 | 시야 | AI 시각 | 발소리/환경 | 특징 |
|---|---:|---:|---:|---|
| Clear | 1.00 | 1.00 | 1.00 | 기준 |
| Cloudy | 0.95 | 0.95 | 1.00 | 약한 시야 감소 |
| Rain | 0.85 | 0.85 | 0.85 | 비가 일부 발소리·원거리 총성을 가림 |
| Storm | 0.70 | 0.75 | 0.70 | 강한 환경음·가시성 저하·이벤트 변화 |

날씨는 스킨이 아니라 시야·AI 감지·소음·이벤트·전리품 판단에 영향을 준다. 같은 raid를 저장/로드하면 동일한 환경 상태를 복원한다.

### 출격별 변화

기본 지형은 수작업 고정 구조를 사용한다. 출격마다 적, 순찰, 일반 전리품, 일부 이벤트, 시간/날씨가 seed에 따라 달라진다. 필수 퀘스트 아이템과 무료 탈출 경로는 seed 때문에 사라지지 않는다.

## 5. 이동, 상호작용, 가시성과 엄폐

- 걷기 3u/s, 달리기 4.8u/s, 웅크림 1.65u/s.
- 스태미나 100, 달리기 초당 18 소모, 중단 1초 후 초당 14 회복.

상호작용은 같은 층, 약 1.5u 이내, 실제 접근/시야 조건에서만 허용한다. 문·상자·시체·NPC·작업대·탈출 장치는 공통 interaction 인터페이스를 사용하되 실패 조건은 명확히 분리한다.

장애물 데이터:

```text
footprint
floorId
minHeight/maxHeight
blocksMovement
blocksProjectile
blocksVision
blocksSound
material
penetrationResistance
destructible
```

이동·총탄·시야·소리를 하나의 collision flag로 묶지 않는다.

- 높은 콘크리트: 대부분의 탄과 시야 차단.
- 얇은 목재/유리: 정의된 관통 가능.
- 수풀: 시야·이동·소리 영향, 기본적으로 총탄 차단 아님.
- 낮은 엄폐: 몸을 보호하지만 노출된 머리까지 자동 보호하지 않는다.

총구가 높은 벽 안으로 들어가면 실제 총구를 제한하거나 벽에서 즉시 충돌시킨다. 가까이 붙었다는 이유로 벽 뒤 표적을 맞히지 않는다.

낮은 엄폐 근접 사격 초기값:

- 기본 총구 높이 1.0u.
- 바리케이드 상단 1.15u.
- 서서 전면 0.35u 이내일 때 총구를 1.35u까지 약 0.18초에 들어 올릴 수 있다.
- 경로가 안전하고 상단을 0.05u 이상 지나갈 때만 허용.

## 6. 전투 파이프라인

한 번의 발사는 정확히 다음 순서를 따른다.

```text
입력/상태 검사
→ shotId와 발사 시각 확정
→ 약실탄 소비
→ 산포·반동 결정
→ 총구 안전성 검사
→ 연속 탄도 진행
→ 최초 유효 충돌
→ 피해/방어구 계산
→ 사망/퀘스트/AI 사건
→ 시각·청각 피드백
```

총탄은 실제 총구에서 출발하며 `(x,y,z)` 연속 선분으로 진행한다. 커서 위치에 직접 피해를 발생시키지 않는다.

기본 탄속:

- 권총 100u/s
- SMG 120
- 카빈/AR/LMG 180
- DMR 220
- 볼트액션 260
- 벅샷 90

각 simulation step에서 이전 위치→다음 위치 선분으로 후보와 교차하고 가장 작은 유효 `t`를 선택한다. 물리 쿼리 반환 순서를 명중 우선순위로 쓰지 않는다. 고속 탄에 점 겹침 검사만 사용하지 않는다.

비관통 탄은 첫 장애물/신체에서 멈춘다. 같은 `ShotId/PelletId`가 같은 신체에 중복 피해를 주지 않는다.

발사 간격은 `60/RPM`과 simulation time으로 계산한다. 렌더 FPS와 무관해야 하며 자동 사격은 틱 내부 발사 시각과 잔여 시간을 보존한다.

### 머리/몸 판정

헤드샷은 확률 치명타가 아니라 **탄도가 머리 피격 볼륨과 먼저 교차한 결과**다.

초기 높이:

```text
body: 0.35 <= z < 1.40u
head: 1.40 <= z <= 1.80u
```

장식 깃털, 총열, 가방, 투명 여백은 피격 범위가 아니다. 웅크림·방향·헬멧에 맞는 `HitboxProfile`을 사용한다.

기본 부위 배율:

- 머리 2.0
- 몸 1.0
- 선택적 사지 0.75
- 벅샷 머리 1.35
- 슬러그 머리 2.0

헬멧은 머리, 조끼는 몸만 보호한다.

### 피해/방어구 공식

```text
Dpre = Dbase × ammoFlesh × hitPart × rangeFactor × penetrationCarry × explicitBuff
Aeff = armorRating × (0.5 + 0.5 × durabilityRatio)
q = clamp01((ammoPenetration - Aeff + 20) / 40)
healthTransfer = 0.15 + 0.85 × q
HPDamage = Dpre × healthTransfer
ArmorLoss = Dpre × ammoArmorDamage × (1 - 0.5 × q)
```

방어구 없음/내구도 0이면 `healthTransfer=1`, `ArmorLoss=0`.

방어값 1~4등급: **20 / 40 / 60 / 80**.

초기 최대 내구도:

- 조끼 60/80/100/120
- 헬멧 40/55/70/85

유효거리까지 배율 1.0, 유효거리→최대거리에서 선형 감소. 최대거리 배율은 소총/정밀/LMG 0.5, 권총/SMG 0.4, 벅샷 0.15, 슬러그 0.5.

`DamageResult`는 최소 raw damage, 부위, 거리, 방어구 전/후, 실제 HP 손실, 사망 여부를 반환한다.

### 환경 관통

재질 저항 TUNABLE:

- 유리 10
- 목재 50
- 철 250
- 콘크리트 1000

`cost = resistance × 실제 통과 두께`. `Ebefore > cost`일 때만 관통하고 `Eafter = Ebefore - cost`.

관통 후 피해 carry에 `Eafter/Ebefore`, 탄속에 `sqrt(Eafter/Ebefore)` 적용. 최대 2개 장애물 관통.

```text
조건 충족
→ 구역 안 5초 유지
→ 같은 tick의 충돌/피해/사망 처리
→ 생존/조건 재검사
→ raidId 기준 반입 한 번 커밋
```

같은 tick의 치명타와 탈출이 경쟁하면 **사망 우선**.

### 사망

출격 휴대품은 사망 가방으로 이동하고 거점 창고·계정 화폐·확정 성장 상태는 유지한다. 기본 회수 모드는 최근 사망 가방 1개를 다음 동일 Map 출격에서 회수 가능하게 한다. 새 사망이 발생하면 이전 가방을 제거하는 정책을 사전에 표시한다.

### IndexedDB

- 저장 슬롯 최소 3개, 서로 완전 격리.
- 중요 commit은 transaction journal을 가진다.
- 임시 record 작성 → 무결성 확인 → current pointer 교체 → 이전 유효 snapshot 백업 순서.
- 손상 데이터는 자동 덮어쓰기하지 말고 마지막 유효 snapshot 복구 또는 사용자 복구 UI를 제공한다.
- 로드 순서: definition → containers → items → equipment references → progression/world → UI.
- 초기 스폰 루틴을 로드된 world 위에 다시 실행하지 않는다.

### 브라우저 상태

- `visibilitychange/pagehide/beforeunload`는 보조 체크포인트 신호만 사용.
- document가 hidden이면 simulation, 출혈, 제작, 탈출 카운트, AI를 정지한다.
- reload/새 browser context 후 마지막 완료 commit으로 복원한다.
- IndexedDB quota 실패가 기존 유효 저장을 파괴하지 않아야 한다.

### Export/Import

사용자가 슬롯을 JSON 또는 바이너리 패키지로 export/import할 수 있게 한다. import는 schema·checksum·definition 참조를 검증한 뒤 **새 슬롯 또는 명시적으로 선택한 슬롯에 원자적으로 적용**한다. 손상 파일을 부분 적용하지 않는다.

## 16. 사격장, 디버그와 자동 검증

**2. 진행 기반 난이도 (위협 단계)** — `src/world/threat.ts`
- 위협 단계 = 완료한 Q02·Q03·Q07 수(0–3). 스폰 그룹 단계 = 위협 단계 + (지역 전리품 등급 − 2), 0–3으로 제한 → 농장·수로 −1, 검문소 ±0, 산업 시설·외곽 보급로 +1.
